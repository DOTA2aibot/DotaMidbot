## Какие решения ещё должен оценить человек

Нет правила «last-hit всегда важнее deny/хараса». Кандидаты получают признаки: добитые крипы, ranged, deny, урон герою, предполагаемый kill, мана, риск, время и воздействие на волну. Нынешняя формула — ручное ранжирование кандидатов, **не ML reward**.

Параметры draft находятся в `laning/advanced/config.lua`: горизонт 4 s, до 3 шагов, до 8 целей; резерв маны 15% — штраф, не абсолютный запрет. Веса: creep 10, ranged bonus 6, deny 5, предполагаемый hero kill 40, hero damage 0.025, mana -0.025, estimated risk -0.04, time -0.3, wave damage при цели пуша +0.02 / при удержании -0.012, прогноз обычного gold_min +0.10. Это гипотезы для ревью и сценариев, а не доказанные оптимальные значения. Различие в поведении при одинаковой выгоде определяется стабильным порядком кандидатов. XP не считается дополнительной наградой за LH.

Каталог не означает готовность каждого действия. Передвижение к руне, ward/deward, kite/reposition и deny→secure пока имеют явные маски отсутствующего исполнителя/предиктора. Цепочки нескольких койлов требуют отдельной проверки cross-raze cooldown. Симулятор использует наблюдаемые оценки HP/движения/защиты, не моделирует всю Dota.

Стабильный каталог и разделение observation/option/event помогут впоследствии подключить обучение; отсутствие переобучения или совместимость с ещё не выбранным ML backend не обещаются.

## Что ещё не готово

Backend `Snapshot/Validate/Submit/Events/Record` из [контракта T016](docs/T016_COORDINATION.md) пока отсутствует. Не проверены совместное состояние callbacks, реальные события release/cast, установленный build, реальные modifier stacks, поворот/геометрия и взаимодействие lane/ability callbacks. Это существенная работа интеграции, не переключение флага. Текущий draft не ставить целиком вместо рабочего бота: без backend новый lane mode отдаёт нулевой desire, управлять атакой он не будет.

Артём одобрил поведение и публикацию в чате. Следующий шаг: независимое code review, согласованное подключение исполнения T007/T016 и проверки по порядку один удар, один койл, удар→койл по разным целям, два койла со стаками/expiry, отмена при опасности. Затем общий локальный прогон v0.2/T009, где проверяются покупки, прокачка и лайнинг вместе. T007 не закрывать до интеграции, независимого ревью и фактических игровых критериев.

ZIP содержит только предлагаемые code/test/docs файлы и этот обзор. Существующие общие AGENTS/AI_CONTEXT/ARCHITECTURE/TEAM_WORKFLOW из репозитория архив не заменяет.
