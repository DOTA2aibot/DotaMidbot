# v0.3.24 — T039, кандидат давления под вышкой

Artem (GPT), reviewer Олег (Kimi). База main78ef254, принятая v0.3.23 сохранена
в [BASELINE_v0323](BASELINE_v0323.md). Новый игровой тест ещё не выполнен.

## Что делает

- Под союзной пачкой разрешает подойти ближе, дать средний/ближний койл и давить героя.
  Прикрытие — не просто наличие крипа: вышка уже бьёт достаточно живого союзного крипа,
  который ближе к ней, чем SF. Даже при прикрытии в бюджет входят возможные попадания по SF.
- Без крипов вход возможен только при достаточной оценке урона готовых, оплачиваемых
  текущей маной и геометрически достижимых Raze, с запасом HP на ответ и отход.
  Урон с руки полезен для давления, но не считается гарантированным убийством:
  есть промахи/уклонение. Будущие стаки, spell amp и непрожатые стики не завышают прогноз.
- Бюджет использует живые damage/attack interval вышки, `GetActualIncomingDamage`
  для брони SF, оценку урона видимого героя, соседних крипов и летящих выстрелов.
  Резерв — минимум150 или25% максимального HP; неизвестные данные запрещают вход.
  Прямой маршрут проверяется точками; это не доказательство длины реального пути.
- При фокусе вышки — один `Action_AttackUnit(ally,true)` на более близкого союзного
  крипа. Повтор не чаще3.1с. Через0.35с нужна смена tower:GetAttackTarget(); иначе выход.
  Команда не объявляется успешным переагром по одному API return.
- Давление под пачкой до3.5с, максимум сессии4.5с; лимит погони450, проверка прогресса1.2с,
  cooldown новой попытки4с. Второй герой/иллюзия, фортификация, видимый каст врага,
  потеря прикрытия без lethal-плана, недостаточный HP или закрытый путь → выход.
- Смотрители: личный нейтральный capture-mode отключён; точный watcher target/cast
  отменяется. Другие каналы, включая Requiem, этим guard не отменяются.

## Где написано

`laning/pressure/{risk,entry,watchers,config}.lua` — оценка, сессия, ограничения.
`profiles/tower_pressure/` — личные ROAM/SIDE_SHOP только тестового профиля.
В `ability_item_usage_nevermore.lua` запрет доворота под T1 заменяется условным risk-gate
только при включённом профиле. В `tactical/entry.lua` — выбор Raze по цели давления
и уступка конкурирующих действий. PT/Stick, руны, варды и доставка не переписаны.
`ally_shop.lua` получил только разрешение прежнего тестового закупа в новом профиле,
без смены очередей. `package_bot.py` добавляет отдельный профиль и читает актуальную версию
из source metadata вместо старого hardcodev0.3.21.

## Существенное ограничение

`tower_pressure_test` заменяет весь ROAM SF и отключает SIDE_SHOP capture-походы:
обычных нативных роум-гангов в этом профиле нет. Старый `all_test` этого не делает.
Оценка риска не гарантирует убийство/выживание и не знает скрытые cooldown соперника.
Присланные700/500/3с не используются как гарантия поведения движка: контроль по readback.
Известны пользовательские сообщения о неоднозначности deaggro:
https://github.com/ValveSoftware/Dota2-Gameplay/issues/26859 — это отчёт, не подтверждение Valve.

## Как проверить

Сравнить с хорошей v0.3.23: одна сторона/герой/схожая линия.
1. Союзная пачка под T1, SF здоров: есть короткое давление без дрожания на границе.
2. Вышка переключилась: `tower_deaggro_attempt`, затем `tower_deaggro_readback` либо выход.
3. Без крипов здоровый враг: входа нет. Очень слабый враг и запас SF: короткий заход возможен.
4. Второй враг/потеря прикрытия/мало HP: прекращение погони и выход.
5. Контроль LH, смертей, рун, вардов, PT/стиков; отсутствие helper_error.

События: `tower_pressure_decision/start/exit/end`, `tower_focus_observed`,
`tower_deaggro_attempt/readback`, `ignore_watcher`. Hit/kill не выдаются за подтверждённые.
Офлайн fixtures проверяют решения/приказы, не реальный переагр, попадания или выбор режима C++.
