### Requiem

При старте допускаются только видимые IsHero=true, IsIllusion=false, известный player ID≥0 и другая команда. Известные Tempest Double/illusion modifiers исключены. Неизвестный IsIllusion — отказ. Враг с≤40%HP в700 или ответ на недавнюю атаку при собственных≤30%HP сохраняют смысл исходных правил, но кандидаты теперь фильтруются по настоящим героям.

Отменяется только собственный **ручной** Requiem, подтверждённый legacy Action notification, с совпадающим GetCurrentActiveAbility и IsInAbilityPhase=true, без чужой очереди/канала. Радиус читается из текущих ability special values. Если все отслеживаемые цели остаются видимыми и находятся за радиусом+80, их прогноз тоже снаружи, и это состояние устойчиво150мс — выдаётся одна отмена. Новая настоящая цель внутри радиуса сохраняет каст. Пропажа в fog, неизвестный радиус/прогноз, чужая способность или уже выпущенные волны запрещают отмену.

При угрозе, оправдывающей BKB, можно прервать свой подтверждённый Requiem, а BKB попытаться применить следующим tick. Чужие casts/каналы не очищаются. Отмена после смерти и автоматический death Requiem не присваиваются модулю. Лог пишет окончание phase, но не обещает возврат маны/кд.

### Мана и предметы

Нет жёстких75мана×3 в решении: используются GetManaCost выученных способностей. Clarity — если маны меньше бюджета трёх койлов, нет эффекта clarity, видимых врагов в1000, недавнего урона героя, входящего tracking projectile или опасной башни. Mango — полезный дефицит перед боевым бюджетом; вне боя допускается при отсутствии доступных clarity/bottle и их регенерации. Минимальный полезный дефицит50. Рюкзак/стэш не считаются активным предметом. Покупками и перемещением предметов модуль не занимается.

BKB принимает более осторожное решение в пользу выживания, но не считается защитой от всего. Список известных control spells ограничен и расширяем в config. Входящие tracking spells направлены на самого бота; линейные проверяются на пересечение по position/velocity/radius в ближайшие1.2с. Видимый GetTarget врага — лишь target hint, что отмечено в evidence. При собственном burst и видимом магическом потенциале API estimate может разрешить BKB; он НЕ доказывает, что прошлый урон был магическим или кд врага готовы. Скрытые enemy cooldown/mana не читаются.

Basic bottle/wand/stick/flask сохранены отдельными Consider-проверками. Когда tactical включён, старый ItemUsageThink не вызывается после отказа безопасной clarity — иначе он мог бы обойти новый запрет. Это нужно согласовать при окончательной интеграции с Олегом. Tango/Satanic/прочие активные предметы этим кандидатом не добавлены; исходный PR43 их также не реализует. Не заявляется универсальный native item fallback.

PT читает текущий GetPowerTreadsStat после каждого переключения. Нет предположения, что два приказа в одном кадре уже дадут INT. Смена состояния ограничена по числу попыток/времени; при неизвестном stat API baseline spell не блокируется навсегда. STR при опасном low HP выше INT. Во время каста/канала переключения не выдаются. Фактическую экономию маны от PT нужно измерить в клиенте.

### Лес

Нейтральный кандидат рассматривается только в FARM либо если текущая атакуемая цель — этот нейтрал. Видимые lane creeps и enemy heroes уступать ему не должны. Считаются цельные области попадания, текущие range/radius, souls/дебафф там, где значения доступны, GetActualIncomingDamage и резерв двух койлов после расхода. Неизвестные бонусы не превращаются в гарантированный kill. Feast разрешён перед достаточно здоровой группой, если остаётся и мана на следующий койл, и резерв. Клиентская IsFullyCastable остаётся обязательной.

Перед койлом проверяется фактический центр относительно текущего facing. При необходимости — только48-unit доворот с passability/tower guards и throttling. Ни походов по лагерям, ни нового attack/movement mode, ни погони за нейтралами нет.

### Варды

Observer не получает случайную точку ниже hill-профиля. Кандидат должен находиться в cast range, на высоте минимум3 и выше обеих bank-точек, геометрически покрывать одну power rune и две точки мида с запасом по радиусу1600. Проверяется высота вдоль лучей и коридор известных деревьев. Ward cliff может быть непроходимым для героя — это не запрет поставить вард.

Это **консервативная модель покрытия, а не точный движковый LOS**. После установки пишутся новая entity+трата заряда, owner, высота, фактический vision range и team visibility rune/mid. Последняя не приписывается эксклюзивно варду. Если подходящей точки уже в пределах каста нет, модуль ждёт подходящего положения Valve, не ведёт героя отдельно к cliff. Это может означать отсутствие установки в конкретном матче — no lowground fallback выбран намеренно.

Sentry — центр мидовой реки, height≤1, доступная точка без дубликата. Это detection, не замена observer vision. Режим dispenser откалиброван по собственному матчу9082079610: в22–24с toggle=true, затем подтверждён observer в24.1с. Новый code не использует обратное предположение. Для смены режима — отдельный tick, readback и максимум2 попытки, затем backoff. Если при toggle меняется заряд, дальнейшая постановка отключается до нового state, чтобы не делать повторные ошибочные приказы. В новом клиенте это соответствие всё равно требует короткой проверки.

## Как Олегу (Kimi) подключить

1. Сверить свои свежие изменения item/ability с ADR0008. Покупки/инвентарь/курьер остаются его текущему коду. Не мержить41/43/46 ради этого кандидата автоматически.
2. Внести новые tactical файлы. `package_bot.py` уже собирает все Lua под laning, менять его не требуется.
3. Запустить генератор на **своём актуальном** ability-файле и выбрать новый путь результата:

```powershell
python -X utf8 tools/attach_tactical.py --source ability_item_usage_nevermore.lua --output candidate/ability_item_usage_nevermore.lua
```

4. Diff должен содержать только защищённый footer после функций. Генератор не перезаписывает source/output, не пишет в Dota и не содержит копии старого gameplay-файла для замены нового. Footer передаёт getfenv(1); `_G` может быть другим окружением.
5. При итоговой интеграции добавить этот footer, общий version/CHANGELOG bump, проверить profile/controller и сборку; отдельный повторный review. Неполный callback contract оставляет исходные callbacks без подключения. Module import failure не отменяет старый файл.
6. Тестировать новый кандидат с backup; установленная v0.3.5-all-test этой задачей не заменяется. По желанию `config.enabled=false` делегирует исходные callbacks.

## Игровой протокол после согласованной интеграции

- Requiem: реальный враг рядом → старт; все видимо вышли за область → одна отмена; цель в fog → не считать убежавшей; оставшаяся цель → не отменять; иллюзия/unknown → не стартовать. После отмены нет покадрового повторного запуска.
- BKB: входящий стан по себе/на пересечении; летящий мимо скилл, обычная тычка и союзный скилл как отрицательные проверки. Подтвердить реальный cooldown/modifier, не только order_attempt.
- PT: прочитать stat INT перед release, AGI после, STR при lowHP+damage; нет toggles во время подготовки ульта и нет цикла.
- Мана: дефицит на три койла и спокойствие → clarity; бой с полезным дефицитом → mango; активный реген/полная мана → сохранение расходника; slot6–14 → никаких попыток использования.
- Лес: FARM в уже достигнутом лагере → Feast/raze при достаточной мане, реальные попадания и возврат на обычное управление. Enemy/wave/низкая мана → отказ от дополнительного лесного скилла.
- Вард: подтвердить terrain и обзор на актуальной карте, правильный цвет, rune+mid visibility после установки, readback dispenser. Невозможность найти точку записывается отдельно от API failure.

Все новые записи имеют префикс `[MIDBOT tactical]`, schema midbot-tactical-1. События: requiem_submitted/cancel/order/resource change, mana_decision, bkb_decision, treads state/timeout, neutral_decision, ward_plan/placement/mode/unknown. Старый parser observer_report.py эти записи ещё не анализирует: сохранять полный log, не считать отсутствие в observer summary отсутствием действия. Написание отдельных reward labels/обучение не входит.
