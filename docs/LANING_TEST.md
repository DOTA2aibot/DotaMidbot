## Конкретный baseline: что предлагается обсудить

1. Действует в первые 0–600 игровых секунд, только для SF. После окна — нулевой desire, работают другие режимы. Возврат к прежнему встроенному laning **не** гарантируется: наш файл переопределяет lane mode, а не оборачивает старый.
2. Смерть, disable, активная способность/канал, retreat, HP <35%, видимая опасная башня или численное меньшинство среди видимых героев → yield. Yield не вызывает move/stop: это уступка управления, а не реализованный retreat. Не видим скрытого противника — не можем считать его отсутствующим.
3. Приоритет ordinary last-hit выше deny. При двух last-hit выбирается меньший ETA попадания, затем меньший HP. Цель должна быть видима, жива, доступна физической атаке и уже внутри attack range. За крипом не догоняем; перемещение отдельно к позиции линии.
4. Оценка удара: attack damage минус base variance, затем физическое снижение цели; дополнительный запас 5%. Сравнение с текущим HP + неотрицательный regen × (windup + projectile travel). Это НЕ прогноз урона всех крипов/героев. Урон случайный, miss/high ground/deny особенности и единицы attack point нужно проверить в клиенте.
5. Deny только по союзному крипу с HP <=50% и в пределах оценки одного удара. Не бьём заранее здоровых своих крипов.
6. Harass — один обычный удар по ближайшему доступному видимому герою в текущем радиусе атаки. Только HP >=65%, без видимого численного меньшинства, вне проверенной зоны башни, если рядом нет крипа с HP в пределах 1.5 наших ударов. Нет погони за врагом. Враг-иллюзия сейчас может быть выбран для harass: это отдельное возможное уточнение, не скрытая оптимальность.
7. По здоровым вражеским крипам не бьём просто ради атаки/пуша. Пока нет цели, позиция — на 250 units позади фронта mid; двигаться, если дальше 175 units от неё. Проверка башни только по видимым башням рядом и конечной точке, не по всей траектории движения.
8. После нашего приказа атаки не выдавать другой обычный приказ в течение оценки полного attack cycle. Это грубая защита от отмены windup, не точное знание факта выпуска снаряда. Перед исполнением цель и дистанция перепроверяются; Think читает свежий HP, даже если GetDesire использовал короткий cache.
9. Частота решений — 0.15 s. `Action_AttackUnit(target, true)` означает одиночную атаку. Wait/no_new_order не отменяет прошлую команду. `Action_ClearActions` намеренно не добавлен, чтобы не чистить очередь способностей другой стороны.

## Для будущей оценки и модели награды

Лог `[MIDBOT lane]` содержит policy/schema version, actor_id, seq, game_time, reason, kind, status, свой HP, числа видимых героев, выбранную цель/HP/оценку урона/ETA при наличии, last_hits/denies и их приращения. Неизвестные поля цели отсутствуют, а не превращаются в нули. target_id — только локальный ID handle в этой Lua-сессии, не глобальный/межматчевый ID.

- `submitted` означает отправку вызова API. Не означает попадание, урон или last-hit.
- Delta last_hits/denies — фактическое изменение счётчика героя между логами. Оно помечено `outcome_attribution=interval_only`: добивание мог дать рейз из T016. Нельзя приписывать его последнему обычному удару автоматически.
- Консольный лог не содержит полного списка всех наблюдений/кандидатов, стабильного match ID, событий каждого попадания или готового train/test split. T006 должен подтвердить экспорт/полноту, прежде чем называть это RL-опытом.
- В policy **нет** reward/penalty, подбора весов, PPO или обучения. Пороги — предложение людям для обсуждения.

Кандидаты для будущего reward (ещё не реализованы): реальный last-hit и deny; контролируемая разница нанесённого/полученного урона при harass; смерть и неоправданный риск. Для урона/смерти/причинной связи нужен отдельный сбор подтверждённых событий. Не давать положительную награду за сам приказ attack, не штрафовать каждое ожидание: иначе модель может научиться спамить ударами и пушить линию вместо фарма. Числовые веса выбирать отдельным решением, а не прятать в этот код.

## Проверки, выполненные локально

Python 3.13 + lupa 2.8, runtime Lua 5.1: 14 policy scenarios + 11 adapter scenarios + 2 JSON checks = **27** проверок. Adapter тестирует сами новые файлы с mock API: неизменность приоритета, отсутствие двойного учёта самого SF, устаревший HP/невидимая цель, casting/retreat, башня, одноразовый приказ, счётчики, выбор командного слота с не последовательными PlayerID. Это не Dota runtime.

```text
lua tests/laning/test_policy.lua
lua tests/laning/test_adapter.lua
```

При установленном Python/lupa можно выполнить оба и JSON-проверки через `python tests/laning/run_tests.py`. На машине GPT lupa установлен в локальную папку инструментов; в игровой пакет Python не входит.
