## Code review PR53 — без внесения исправления

### [P1] Прекращение PICK_UP_RUNE закрывает цикл без подтверждённого результата

[runes.lua:81–86](https://github.com/DOTA2aibot/DotaMidbot/blob/0dc2e604f6a6f6f0178cf5abb0d41a714564d21c/laning/economy/runes.lua#L81-L86)
и [423–434](https://github.com/DOTA2aibot/DotaMidbot/blob/0dc2e604f6a6f6f0178cf5abb0d41a714564d21c/laning/economy/runes.lua#L423-L434).
После pickup_seen смена action помечает done_cycle, даже если действие перебито,
целевая руна ещё AVAILABLE и bottle не менялся. Последующие free_grab/selector
исключают её как already_resolved. Событие честно пишет outcome=unknown, но
поведение уже считает цикл закрытым. Две ветки (Decide и Think) воспроизведены
на реальном Lua51 коде: AVAILABLE1/bottle0/прерываниеmove → already_resolved.

Рекомендация: отделить attempt_finished от unavailable_for_cycle/confirmed_pickup.
Нужна согласованная readback-проверка по видимому status и собственным изменениям
bottle/resource/modifier, где доступны; disappearance не приписывать автоматически
себе. Unknown/interruption не давать credit и не закрывать как успешный цикл.
Одновременно сохранить отдельный budget/backoff неудач из следующего пункта,
чтобы исправление falsepositive не вернуло бесконечные походы.

### [P2] После отказа/таймаута тот же спот доступен снова через10сек

[runes.lua:318–319](https://github.com/DOTA2aibot/DotaMidbot/blob/0dc2e604f6a6f6f0178cf5abb0d41a714564d21c/laning/economy/runes.lua#L318-L319).
Leave стирает failed_pickups/backoff/deadline и оставляет лишь общий retry_after.
Для rejected/timeout нет памяти об уже потраченном бюджете именно(rune,spawn_cycle).
После10сек видимый AVAILABLE снова выбирается. Лог показывает3длинных повторения
плюс короткий подход; отдельное Lua воспроизведение подтверждает повтор в том же
цикле. Это самостоятельная причина траты времени даже до выяснения client pickup.

Рекомендация: bounded per-rune/per-cycle budget, отдельно от факта успешного подбора;
неудачи не должны моментально сбрасываться при выходе из mode. Разрешать повтор
по новой существенной информации/состоянию или ограниченному cooldown, а не каждые
10сек без конца. Другую руну и новый spawn_cycle не блокировать. Добавить regression:
несколько silent rejects → возврат к линии без новой длинной попытки к тому же
споту; изменившийся status/новыйcycle → корректное повторное рассмотрение.
