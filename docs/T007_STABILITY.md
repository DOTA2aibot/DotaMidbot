# T007: выход на mid и одна атака — кандидат v0.2

Owner: **Artem (GPT)**. Reviewer и игровой запуск: **Олег (Kimi)**.
Base: `2556564a505f20b366dec6820b890de3174ccd25`.

## Зачем этот патч

В игровом прогоне `observe-2026-11-08-01` новый модуль загрузился, но все 525 runtime-записей были `observed_no_orders`. Добивания/deny — 0/0, к 9:27 герой имел уровень 2. В режиме observe это не проверка исполнения лайнинга. Собственный mode-файл не предоставлял стандартного лайнинга, а новый исполнитель не отдавал приказов.

Связь модулей наблюдалась: 140 записей true / 385 false. Частота записи около секунды не доказывает частоту вызовов callbacks; причина переключений по старому файлу не определяется. `missing_methods={}` касается перечисленных проверок, а не всех методов и их семантики. Наличие Necromastery подтверждает имя, но не всю модель душ/стаков. В старом логе есть собственный снаряд с caster/location без handle; этого недостаточно для калибровки timestamp-only подтверждения.

## Что меняется

| Файл | Изменение и назначение |
|---|---|
| `laning/runtime/config.lua` | Новый default `lane_probe`: ограниченный выход на mid и одна диагностическая атака. Калибровочные поля остаются false. |
| `laning/runtime/backend.lua` | Короткие шаги к mid front, локальное приближение к крипу; атака только в дальности и возле mid. Один атакующий приказ на загрузку. Свежая проверка угроз перед API. |
| `laning/runtime/entry.lua` | Явные причины уступки/ожидания; повышенный приоритет тестового lane mode. В паузе heartbeat режим сохраняется, но команды блокируются. Смена активного режима сбрасывает короткий кэш. |
| `laning/runtime/guard.lua` | Возраст увиденного/принятого ability heartbeat, число вызовов, состояние ACK/lease. Прежний TTL 0.35 сохранён, проверки владения не обходятся. |
| `laning/runtime/observe.lua` | В наблюдение добавлен фактический active mode. |
| `tests/laning/` | Реальный принятый ability callback зафиксирован как точный test fixture; добавлены проверки общего пути и отказов. |

Покупки, корневой файл способностей, назначение линий, игровой номер, STATUS/CHANGELOG не меняются. Каталог из 25 вариантов и продвинутая модель сохраняются. PR26 с Feast of Souls сюда не включён и отдельно не ревьюился.

## Граница поведения

`lane_probe` — диагностический режим. Он не является готовой стратегией фарма. После одного атакующего приказа повторных атак не будет даже при таймауте. Нулевые LH после него возможны и сами по себе не означают ошибку: проба проверяет приказ/выпуск, а не выбирает гарантированное добивание.

Движение: до 250 units за приказ к текущему mid front; возле линии — ограниченное приближение к видимому крипу. Конечная точка должна быть проходима и вне наблюдаемой угрозы вышки. Это не полный поиск безопасного маршрута.

При видимом вражеском герое ближе 900 units, наблюдаемой угрозе вышки, низком HP, недоступных данных или RETREAT проба уступает управление. Неизвестность за пределами видимости не доказывает безопасность. Собственного полноценного retreat этот патч не добавляет.

Выбор lane mode и владение приказами разделены: даже при ненулевом desire без свежего heartbeat и ACK команд не будет. Это удерживает тест от переключения на руны между планами, но не отключает все остальные режимы Valve. Если другой режим выигрывает приоритет, это будет видно по active_mode и think_calls.

`observe` по-прежнему не отправляет приказов и не обещает штатный laning fallback. Простая замена desire на число не восстанавливает стандартный Think. Скрытый непроверенный fallback этим патчем не вводится.

Автономные способности Олега продолжают работать вне активных планов. Поэтому первый сценарий проводить без вражеского героя рядом; диагностика не является глобальным выключателем его способностей.

## Как проверить в игре

1. Взять всю тестовую сборку этой ветки. Сохранить прежнюю установленную папку bots и установить новый набор Lua целиком. Не накладывать три резервных файла поверх нового runtime. Локальный запуск и запись консоли — тем же уже проверенным способом.
2. В `laning/runtime/config.lua` оставить `operation="lane_probe"`, `stage="attacks"`, `option_allowlist=nil`, `max_probe_orders=1`. В build указать SHA кандидата из PR/manifest, run_id сделать уникальным. Никакие `*_verified` не включать.
3. Новый локальный матч. Для первого короткого сценария нужен противник/сценарий, не выставляющий вражеского героя рядом с SF: дуэль проверяется позже. Не отключать защиту ради теста.
4. До пяти минут записать выход героя с базы к mid и одну атаку по крипу. После одного атакующего приказа завершить сценарий; дальнейший фарм этот режим не обещает. Если приказ не появился, сохранить лог ожидания/отказа.
5. Передать полный console log, SHA, версию клиента, конфиг и время проблемного момента. Предпочтительно передать файл участникам напрямую; крупные новые журналы в обычный Git не добавлять.

Ожидаемая цепочка: доступное перемещение → `waiting_owner` / `awaiting_ability_plan_ack` → `submit` → `move_completed`; затем для атаки `submit` → `attack_released` либо `rejected` с причиной. Получение ACK обычно требует следующего callback, а не мгновенного успеха в первом тике.

Выпуск подтверждается новым собственным projectile и изменением записи атаки; handle может отсутствовать, тогда используется новое число снарядов рядом с источником. Таймер не объявляет выпуск. `GetLastAttackTime` отдельно не считается доказательством, пока не проведена калибровка.

## Что смотреть в логе

- `hero.active_mode`, `driver.desire_calls`, `think_calls`, `leave_calls`: выбирается ли lane mode и доходит ли выполнение до Think.
- `integration.ability_calls`, `lane_age_s`, `ability_seen_age_s`, `ability_accepted_age_s`: вызывается ли ability callback и насколько свежа связь.
- `integration.lease_state`: есть ли запрос и получен ли ACK конкретного плана.
- `reason`: например `ability_heartbeat_not_ready`, `lane_probe_unsafe`, `safety_yield`, `current_action_busy`, `probe_limit_reached`.
- `diagnostic_probe=true`: эти записи не выдаются за решения обучаемой политики или готовые labels/reward.

Не повышать TTL/лимит попыток для обхода отказов. Если observed release отсутствует, отдельно сопоставить игровой кадр и события клиента. Если герой не идёт по маршруту, передать координаты и reason; путь нельзя объявлять проверенным по mock-тесту.
