# v0.3.15 — перемещения v0.3.12, ПТ и Stick/Wand

Owner **Artem (GPT)**, reviewer **Олег (Kimi)**; T036/T037, PR55.
Пользователь прямо выбрал v0.3.12-ward-recovery как baseline перемещений.

## Что восстановлено

Полностью удалены исходники courier ROAM guard, его конфигурация, профиль,
тесты и generated flag из v0.3.13. В v0.3.14 режим уже не исполнялся;
его физическое удаление само по себе не доказывает устранение дёрганья.
Сохранены **ровно существовавшие в v0.3.12** ground-only ITEM-mode,
команды доставки курьеру, read-only courier observer и vision.
Это не откат к версии до первоначального ITEM-mode.

33 файла движения/способностей/vision сверяются с хешами исходного
установленного архива v0.3.12. В объединённой сборке дополнительно
проверяется равенство всех прежних runtime-файлов за исключением
явно перечисленных изменений PT/Wand и metadata. PR53 остаётся
на прежнем 0dc2e60; руны не переписываются.

## ПТ ниже приоритета каста

- Обычный `PT.Before` не нажимает предмет, не ждёт readback и не резервирует
  способность: готовый Raze/Requiem проходит сразу при любом атрибуте ПТ.
- При отсутствии ПТ нет подготовки и блокировки следующего выбора.
  В старой v0.3.14 воспроизведено: выбор Raze1, через33мс Raze2 → отказ
  второму, несмотря на отсутствие ботинка. Это реальный дефект; связь со всеми
  дёрганьями в конкретном матче не доказана.
- Обслуживание ПТ выполняется **после** обычного ability callback, только если
  собственный cast/face/ward не использовал бюджет приказа. В ItemUsageThink
  фоновых переключений нет. Bottle также не ждёт переключения.
- По умолчанию AGI. Краткий свежий hint выбранной способности может подготовить
  INT в оставшееся свободное окно. Новый готовый cast не ждёт завершения этого
  перехода. После фазы каста/подтверждения cooldown — возврат AGI при следующей
  свободной возможности, без приказов во время cast/channel.
- Единственный явный `PrepareMana` сохраняется внутри прежней функции ресурсов:
  сейчас маны недостаточно на видимый потенциально добивающий Raze, и проверяется
  возможность получить её через INT/readback, затем Stick/Wand. Он не блокирует
  обычный cast, если тот уже доступен.
- STR больше не выбирается ни при lowHP, ни при побеге. Штатный цикл предмета
  может проходить через STR как промежуточный атрибут. Микросекундные переключения
  не обещаются: остаются bounded readback/max2toggle/0.10с между toggle.
- INT перед **каждым** кастом/BKB/предметом не гарантируется: если оптимизация
  задержит действие, пропускается именно оптимизация. Emergency BKB не ждёт ПТ.

Политика Stick/Wand и raw-карта STR0/INT1/AGI2 сохранены. Расчёты damage используют
свежий GetAttackDamage, без ручного добавления10. Не добавляется новая модель
перемещений или собственный контроллер атак.

## Проверка варда на xx:45

`recovery.Poll → Site.Geometry → Site.Existing → GetUnitList(UNIT_LIST_ALLIED_WARDS)`.
Проверка доступна из любой точки карты. Нет проверки расстояния до SF,
его facing, локального CanBeSeen или IsLocationVisible; нет Action_*.
Она может запланировать следующее окно или разрешить закупку. Фактическая
постановка в следующем окне — отдельное действие с прежними условиями безопасности.
Новый regression test ставит SF далеко, выключает local visibility и проверяет
наличие/отсутствие союзного варда без facing/move/покупок. Lua vision не менялась.

## Проверка в клиенте

Один новый Radiant-mid run >=12мин без пингов: до покупки ПТ проверить свободный
выбор/попадания Raze и LH; после покупки — немедленный Raze при AGI/INT, отсутствие
выбора STR при lowHP, AGI для фарма, Wand1/0charges, варды0/5/10 и удалённыйxx:45.
Если дёрганья сохранятся, нужен точный игровой таймкод/видео для сопоставления с
existing_raze_turn, Rune/ward и нативными приказами. Сравнение двух разных матчей
не доказывает причинность. Courier detours и качество игры пока не объявляются
исправленными. Merge/Done/gameAC требуют независимого review и нового run.
