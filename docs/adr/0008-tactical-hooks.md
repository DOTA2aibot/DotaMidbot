# ADR0008 — явное подключение тактических модулей SF

Статус: **Proposed**. Задача: [T024 / Issue48](https://github.com/DOTA2aibot/DotaMidbot/issues/48). Не считать одобренным до review людей. Основание — прямое согласованное разделение работ Artem в чате08.11.2026.

## Проблема

Олег (Kimi) меняет общий ability/item callback в PR43. Новые Requiem/BKB/PT/нейтральные койлы требуют тех же точек вызова, а обработчик вардов не должен продолжать ставить старые точки. Одновременная правка одного корневого файла создаст конфликт. Вызов дополнительного helper без возврата управления не предотвращает второй приказ в том же кадре.

## Предложенное решение

Новые файлы `laning/tactical/*` и тесты разрабатываются отдельно. Владелец корневого файла при интеграции добавляет один защищённый footer через `tools/attach_tactical.py`, передающий **getfenv(1)**, а не `_G`. До добавления footer код не активен. Ни функции движка, ни методы bot handle не подменяются.

`BindLegacy` сначала проверяет весь контракт. Затем сохраняет исходные собственные Lua callbacks и устанавливает их декораторы. В нём есть idempotency guard. Существующие боевые Consider-функции остаются источником обычных геройских решений; отдельная политика выбирает Requiem только по подтверждённо настоящим героям. Подтверждение собственного начала приходит из существующей observer Action notification ПОСЛЕ вызова API. Один broker хранит бюджет приказа на tick, подтверждения ресурсов, собственный Requiem и PT-план для каждого bot handle.

Порядок до обычного legacy spell handler: наблюдение результата → BKB при видимой угрозе → возможная отмена собственного Requiem → PT/ресурсные предметы → уже достигнутый neutral camp → прежние способности. Пока бот кастует, старый callback продолжает наблюдение, но тактическая проверка идёт до его раннего return по IsUsingAbility.

Активный тактический ItemUsageThink управляет BKB/PT/clarity/mango и поддерживает прежний базовый набор bottle/wand/stick/flask через `tactical/items.lua`. Это **явная смена владельца исполнения item callback после подключения**, а не обещание независимой работы двух обработчиков одновременно. Иначе старые clarity/mango-ветки могут обходить новые safety gates. Оригинальный callback сохранён для `config.enabled=false` и аварийного fallback до выдачи собственного приказа. Новые предметные изменения Олега должны быть сверены с этим набором при интеграции; файлового конфликта нет, но семантическое review обязательно. Inventory/покупки/курьер не перехватываются.

Observer AfterAbilities при включённых tactical wards вызывает только новый ward executor. Старые read-only ward suggestions могут по-прежнему появляться как executed=false; они не являются постановками нового контроллера. Режимы линии и обычные атаки Valve не переопределяются. Для нейтрального койла разрешён только короткий48-unit доворот уже в достигнутом лагере, без маршрута/погони.

## Ограничения

Это разработанный кандидат, а не подтверждённый клиентом релиз. Проверяются Lua5.1, API mocks, реальный pinned root PR43 и генератор footer. Общая игровая версия/CHANGELOG остаются за владельцем интеграции, чтобы не менять общие файлы параллельно. Матч, FPS, текущая геометрия карты, каста/отмены, режимы dispenser/PT и фактические попадания требуют игрового протокола. Отсутствие исключения не подтверждает попадание или получение видимости.

Root contract, callback ordering и semantics observer Action должны быть повторно сверены при обновлении PR43. Ошибка после API не разрешает повтор того же действия в кадре. Fog/неизвестная высота/неизвестный тип цели не превращаются в «безопасно». Обучение и награды этот ADR не вводит.
