# ADR-0001: Baseline до обучения

- **Статус:** Proposed
- **Предложено:** 2026-11-07
- **Принято:** не принято
- **Задача:** T001; проверка T003, T011
- **Автор:** стартовое предложение для команды
- **Согласовали:** никто; требуется согласие обоих участников
- **Заменяет / заменён:** нет

## Контекст

Команда из двух человек хочет своего обучаемого бота. У Олега/Kimi есть 3 Lua-файла SF v0.1, прочитанные в INITIAL_AUDIT; успешного запуска пока не подтверждено. Нет проверенного игрового интерфейса, телеметрии и исходных метрик. Требуется первый полезный результат и возможность независимо работать над gameplay и анализом.

## Альтернативы

| Вариант | Плюс | Ограничение |
|---|---|---|
| Большая LLM выбирает игровые действия | Возможность быстрого семантического прототипа | Отдельная стоимость inference, задержка, нестабильность формата; не даёт готового обучения |
| Сразу end-to-end RL | Напрямую исследует обучаемую policy | Нужны среда, reset, reward, данные, throughput и baseline; ничего из этого не подтверждено |
| Локальный rule-based baseline, затем один обучаемый компонент | Ранний проверяемый результат, fallback и точка сравнения | Потребуется ручная логика и отдельная проверка переноса learned-компонента |

## Предложение

Выбрать третий вариант. Ранний игровой контур — в Lua через проверенный Bot Scripting маршрут. Python — кандидат для offline-анализа. В первом AI-эксперименте менять одно решение, например момент добивания, сохраняя остальные правила и action-space.

LLM, PyTorch, Gymnasium, PPO, transport и realtime inference не являются принятыми зависимостями этого ADR. Точное размещение кода уточняется после аудита; пригодную реализацию друга сохраняем, если она проходит критерии.

## Проверка

T003 подтверждает игровой маршрут на двух машинах. M1/M2 дают baseline и измерения. T011 проверяет возможность и стоимость обучения одного компонента; допустимо решение no-go или supervised/offline исследование. Пока эти проверки не проведены.

## Последствия

Есть общий deterministic по коду, но не обязательно детерминированный по игре baseline. Он поддерживается для сравнения и rollback. Переход к нейросети не гарантирует улучшение; игровой throughput и стоимость данных остаются отдельными вопросами. Большая архитектура и инфраструктура не строятся заранее.

## Условия пересмотра

Аудит выявил работающий иной подход, Bot API недоступен, данные нельзя экспортировать или конкретный learned-компонент требует другого интерфейса. Любая смена оформляется следующим ADR с экспериментальными свидетельствами.
