# ADR0007 — отдельный ограниченный rune/mana профиль

Status: Proposed, 2026-11-08. Owner Artem (GPT), reviewer Олег (Kimi). Issue40.

## Контекст

Вv0.3.3Valve управляет линией/атаками/рунами. Пользователь сообщил об улучшении боя, но ненужных уходах с мида за руной и нехватке маны. Лог9081121671 даёт счётчики и ресурсы, но не показывает target/type руны. Без проверенного selective fallback нельзя обещать изменить только внутренний приоритет Valve и оставить остальную часть того же rune mode нетронутой.

## Предложение

Сохранитьvalve_playкак контроль. Вvalve_lane_economy заменить целиком только rune mode SF на низкое желание и ближайшие видимые river spots без поиска. Новый root mode включается исключительно сборщиком этого профиля; нет собственного laning/attack controller. Цена ограничения — игнорирование остальных рун SF, включая bounty, и всех рун после15:00. Это должно быть явно видно вmanifest/controller/protocol.

Mana hook выбирает/оплачивает только ограниченный дополнительный запас, не исполняет item use и не перестраивает очередь. При неизвестности API/исхода — отказаться от нового вмешательства. Дополнительные данные observer нужны для отдельного решения по frenzy и будущему farm reward; модель не обучается.

## Альтернативы и решение о принятии

Не менять поведение — сохраняется вvalve_play. Поднять все lane desires или перехватывать движение из ability callback — затронет работающий бой и пока отклонено. Возвращатьnilради скрытогоC++fallback — не используется без проверки. Полноценное управление всеми рунами/пачками и обучение остаются другими задачами.

Промоут профиля после повторяемого игрового A/B и независимого review. До этого ADRнепринят, кандидатнеDone, установленнаяv0.3.3неперезаписывается публикацией.
