# ADR0005 — явные профили Valve play / runtime probe

Status: **Proposed**. Связано с Issue #33 и Proposed ADR0004. Owner: **Artem (GPT)**; reviewer: **Олег (Kimi)**. Принятие обоими людьми не утверждается.

Контекст: диагностический mode_laning переопределяет стандартный режим, держит приоритет во время heartbeat-пауз и после600 секунд перестаёт исполняться. Нулевой desire не является вызовом заменённого C++ Think. Доступный и проверенный динамический API такого вызова не установлен. Документация Valve недоступна при текущем чтении (403); утверждения из сторонних пересказов о nil/false не приняты за контракт.

Предлагаемое решение: обычное дерево и сборка valve_play не содержат корневого mode_laning или bot entrypoint. Способности/покупки остаются собственными. Исходный entrypoint сохраняется в profiles/lane_probe; сборщик помещает его в корень только отдельного probe ZIP и включает runtime через laning/profile.lua. По умолчанию guard не создаёт канал/lease и не блокирует автономные способности. Полное воспроизводимое переключение — установка целой папки и новый матч, не hot reload.

Это **статический выбор контроллера перед матчем**, не автоматическая передача Valve внутри матча. Если нужен совместный штатный lane+runtime в одном матче, это следующая задача с отдельной проверкой engine semantics и арбитража приказов. Продвинутый каталог/механика T007 сохраняются и проверяются в probe, но показатели valve_play не объявляются их качеством и не выдаются за обучающие labels собственной политики.

Альтернативы: убрать лимит600 (продлевает диагностический режим вместо полноценной стратегии); вернуть0/nil/false из тех же callbacks (не подтверждает восстановление native Think); написать ещё один упрощённый собственный фармер (меняет модель и scope); встроить controller в другой engine mode (требует новой проверки владения и контрактов). В этом кандидате они не реализуются.

Проверка: реальные Lua5.1 callbacks, отключение guard/runtime в play, неизменность поведения probe, состав ZIP и полная замена старой папки. Отдельно обязательны игровой прогон за10:00 и наблюдение фактических приказов/режимов; файловый контракт не доказывает безошибочность стандартного ИИ текущего клиента. После ревью людей и игрового свидетельства ADR может быть принят/уточнён.
