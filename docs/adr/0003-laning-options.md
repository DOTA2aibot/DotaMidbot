# ADR-0003: совместные варианты планов для лайнинга SF

Статус: **Proposed**. Дата: 2026-11-07. Задачи: T007, интеграция T016/T018/T006. Основание: прямые комментарии Артёма о совместных атаках/рейзах, состояниях врага и намеренном пуше. Пока не подтверждён обеими сторонами.

Проблема: независимые callbacks для атак и способностей могут отменять друг другу действия; жёсткая очередь last-hit/deny/harass запрещает полезные комбинации и не даёт подходящего вариативного интерфейса для ML.

Предложение: постоянный каталог опций с параметрами, динамические маски, короткий событийный forecast и scheduler с подтверждёнными release/complete. Один владелец приказов на героя; отдельные модули наблюдения/knowledge и выбора, без скрытого enemy state.

Альтернативы: оставить независимые эвристики (дешевле, но конфликтуют приказы); сразу обучать primitive per-tick policy (больше свободы, но сначала нужны проверенные observation/execution/reward); описать только комбинации без кода (не проверяет тайминг/маски). Выбранный локальный draft реализует ограниченное подмножество планов и явный protocol seam, не обещая полный Dota simulator.

Последствия: требуется совместный backend T016, combat/observation collector T006 и runtime-probe. Пока seam не подключён, default advanced lane mode не выдаёт приказы; опции обучения сохраняют IDs с недоступными masks. Baseline utility отделена от reward; правила патча берутся из runtime/проверенного профиля.

Критерий принятия: review обеих сторон + проверка источника release/complete, shared actor ownership, профиля урона/стака/душ и минимум одного комбинированного игрового сценария. До этого Proposed; no silent migration to main.
