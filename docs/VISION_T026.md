xx:45, обычная очередь шмоток не блокируется. Неизвестный результат purchase

а не затирает их schedule_complete. Readback pendingcast может завершиться после
конца окна, но новые приказы после него запрещены. Координаты ниже не менялись.

## Автоматическая постановка включена

calibration_only=false. fixed_location хранит указанные XYZ, без случайного поиска
или auto-adopt другого союзного варда. Если GetGroundHeight недоступен, сохраняется
проверенный Z128. Диагностика сообщает human_ward_coordinate_pinned и provenance
матча, но не выдаёт ручной успех за проверенную автоматическую постановку SF.

Окна0:00–0:30,5:00–5:30,10:00–10:30. Внутри окна обычный фарм/deny/AA уступает;
cast/channel/queue, retreat/evasion, HP<70%, недавний урон героя, враг<=450,
атакующий/таргетящий SF враг и опасная башня выше. Начатая Rune имеет приоритет;
политика53 не меняется. Окно10:00 совпадает с руной: если Rune/угроза заняла всё
окно, будет явный missed, а не поздний поход. Безопасность/stock/path могут помешать
уложиться в30с, поэтому безусловной гарантии времени нет.

Не более одной подтверждённой постановки на окно; максимум8с на фазу,1400ед подхода
сверх cast range,2с без прогресса,3с retry. После конца окна новые приказы запрещены,
но уже выданный itemcast получает до3с для readback. Единственный executor проверяет
новую entity и расход заряда, пишет requested_location/actual location/offset.
Timeout не является успехом. PT/regen/обычные own spells уступают выбранной фазе,
emergencyBKB выше, observer пишет; на выходе не стираются новые чужие приказы.

Первый Observer после Tango в стартовой очереди. За90с до следующего окна можно
подготовить один запас, учитывая inventory/backpack/stash/owncourier и pendingunknown.
Прежний courier handler доставляет предмет. По5минциклу допускается около1мин overlap
только предыдущего собственного подтверждённого ward; чужие/unknown не дублируются.
Вне окон нет catch-up походов и нет бесконечных новых покупок по истечению lifetime.

all_test назначать только команде SF, противнику Valve/default. Согласованные простые
союзные покупки без вардов, Tango и остальные способности/предметы сохраняются.

В фактическом v0.3.10 run SF поставил собственные варды на4.0667с и614.7334с:

послеspawn, второеtrue; teamvisibility не гарантирует exclusivewardLOS, точка не меняется.

Prefetch теперь90с: новый Observer можно купить с210с/510с (3:30/8:30), один запас
с учётом всех собственных мест. Существующий запас не покупается повторно. Courier
забирает вместе с обычными вещами; в пределах этой подготовки безопасный swapObserver
изbackpack разрешён до начала окна, чтобы успел пройти item cooldown.

`vision_supply_state` пишет только изменение местоположения/готовности: active,
active_castable,backpack,stash,owncourier,total,slot/windowstart/beforewindow.
`vision_delivery_observed` появляется лишь при переходе вactive inventory по readback,
не по purchase/courier API return. Если доставка опоздала, запись продолжается и между
окнами; во время следующего prefetch учитывается уже имеющийся вард.

Существующий root courier handler дополнен узким правилом: запланированный Observer
вstash, своего courier health>=80%,alive, RETURNING_TO_BASE иknown fountain distance
<=1200 → разрешён TAKE_AND_TRANSFER, не чаще10с. Активную delivery не разворачивать;
far/dead/lowhealth/unknown/foreign не трогать. Idle/base обычных вещей без изменений.
`vision_courier_attempt`/wait показывают попытку/отказ, а не доказанную доставку.
Источник значений courier states: Valve bot worldstate protobuf в SteamTracking,
https://github.com/SteamTracking/Protobufs/blob/master/dota2/dota_gcmessages_common_bot_script.proto .
Числа enum не hardcode в решении: используются доступные COURIER_STATE_* constants.
