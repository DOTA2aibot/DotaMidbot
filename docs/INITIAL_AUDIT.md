## Факты, дефекты и проверяемые гипотезы

### 1. Запуск не доказан — приоритет T003

CHANGELOG сообщает о неудачном первом тесте. Старый README описывает Workshop как доступный маршрут, но нет item ID/URL, лога или подтверждённого успешного run. Нельзя считать переход в Workshop уже решённой проблемой. Сначала подтвердить загрузку скрипта и вызов callback, затем поведение.

### 2. Закупка теряет позицию независимо от результата — T017

В `item_purchase_nevermore.lua`, строки 37–41, после вызова покупки безусловно удаляется первый элемент списка. Результат вызова и наличие предмета не проверяются. При отказе покупки очередь всё равно сдвинется. Само имя `Action_PurchaseItem` и допущение «финальные компоненты докупаются сами» требуют проверки по фактическому API. Исправление должно учитывать return/result, компоненты, stash/courier и повторную попытку; не добавлять предмет в тестовый инвентарь мысленно.

### 3. Подсчёт крипов не проверяет общую область поражения — T016

В `ConsiderRazeOnCreeps` проверяется только расстояние до героя. Крипы на одной дистанции, но по разные стороны героя увеличивают общий count. Три таких крипа могут дать count >= 3, хотя в одну переднюю AoE они не попадают. Кроме того, комментарий обещает 2+, а код использует 3+. Нужна проверка точки AoE с учётом facing и целей, а не только радиального кольца.

### 4. Способ вызова рейза и API движения — T016

Код вызывает `Action_UseAbilityOnLocation` для рейзов и использует `GetVelocity` для упреждения. Наличие этих строк не доказывает их корректность для текущего Bot API и типа Shadowraze. Проверить ability behavior, доступные методы и необходимость поворота героя в установленном клиенте; сохранить отдельные сценарии цели впереди/сзади/сбоку. Здесь не объявляем конкретную замену уже протестированной.

### 5. Mid lane и прокачка не определены явно — T018

Выбор SF в пуле не является назначением mid lane. Нет собственного lane assignment, AbilityLevelUpThink или подтверждения, что штатный fallback делает это правильно вместе с custom ability/item callback. Без уровней способностей IsFullyCastable может не дать кастов. Это проверяемый пробел, а не доказанный crash.

### 6. Desires и эвристики ещё не обучаемая policy

Desire используется как проверка > 0 при фиксированном порядке условий. Отдельного обучения, reward, dataset, checkpoint и интерфейса step/reset нет. HP/mana/distance constants — параметры эвристик, не обученная модель. Числа дальности и cast point также нуждаются в сверке с текущим build.

## Где проект находится

**Ранний rule-based прототип: часть M1 написана до закрытия M0.** Не начинать с переписывания в Python или самостоятельного игрового движка. Довести существующую Lua-базу до воспроизводимого запуска, подтвердить каста/покупки/прокачку, снять серию baseline и только затем решать, что обучать.

## Происхождение и лицензии

Код содержит упоминание Valve bots_example; README перечисляет ModDota и RMMAI. Это не доказывает ни копирование, ни оригинальность. Авторы подтверждают происхождение фрагментов и выбирают лицензию в T001. LICENSE в исходном репозитории отсутствует. Внешний bota использован только для обзора; его код в комплект не переносится.
