# PR30: выбор одного SF для native 1v1 Solo Mid

Версия: **MIDBOT v0.3**. Исходный PR Олега (Kimi); исправление и offline-проверки — **Artem (GPT)** по прямому поручению пользователя.

## Что делает код

- При `SOLO_1V1=true` и игровом режиме **1v1 Solo Mid** выбирает SF одному бот-слоту своей стороны. В обычном режиме, например All Pick, сохраняет командный пул.
- `SOLO_1V1=false` отключает ограничение выбора и в native 1v1.
- Имя первого бота всегда `MIDBOT v0.3`; профиль выводится отдельно в `[MIDBOT selection]`. Длина списка имён не используется как доказательство числа игроков.
- Сохраняет выбранных героев, не переписывает человеческие picks и не переключается на другого solo-бота при перестановке списка player IDs.
- При неизвестном режиме/именах, человеке на стороне solo-бота или уже выбранных лишних бот-героях не добавляет новый pick и выводит причину. Неверный существующий герой не заменяется автоматически.

Код **не удаляет бот-слоты и героев из лобби**. Native 1v1 и один pick должны быть проверены совместно в клиенте. Если движок после выбора сам создаёт героев для остальных слотов, это обнаруживается по составу матча; такой прогон не является чистым 1v1 и требует отдельной настройки лобби. Прятать лишних героев или называть их отсутствие подтверждённым этот патч не будет.

## Как провести проверку

1. Взять полный согласованный снимок после PR30. Не смешивать одиночные файлы веток.
2. Создать Local Host с режимом **1v1 Solo Mid**, а не All Pick. Для стороны SF выбрать локальный скрипт; для стороны человека — сложность ботов «Нет / None». Человек должен находиться напротив SF, не в его команде.
3. Сохранить лог с начала выбора героев. Ожидается `[MIDBOT selection] profile=solo_1v1 game_mode=21 ... selected_bot_heroes=1 ... status=check_match_roster`.
4. После загрузки проверить таблицу героев и карту: SF — единственный герой своей стороны, соперник — единственный герой противоположной. Записать фактический состав, настройки и версию клиента. `bot_slots=5` при одном выбранном герое само по себе не доказывает ни появление, ни отсутствие остальных героев.
5. Если видно `extra_bot_heroes_no_pick`, `human_on_bot_side_no_pick`, `unexpected_solo_hero_no_overwrite`, неизвестный режим или имена — сохранить лог и исправить конфигурацию; не считать такой прогон успешным 1v1.
6. После подтверждения состава провести короткую пробу движения и одной атаки по [T007_STABILITY.md](T007_STABILITY.md). При `lane_probe` вражеского героя сначала держать вдали от SF: видимый противник в пределах 900 блокирует эту диагностическую пробу. Это не полная дуэльная стратегия.

`hero_selection` диагностирует выбор героев своей стороны. Его callback не обещает непрерывную проверку состава после загрузки и не считает скрытых героев/живые игровые сущности. Финальная проверка обеих сторон выполняется в игре. Для будущей автоматизации нужен отдельный подтверждённый post-load roster probe.

## Что проверено вне игры

148 прежних проверок и 12 новых сценариев выбора: native solo, командный режим, отключение solo, человеческие и непоследовательные IDs, существующий SF/другой герой, повторные callbacks, лишние picks, неизвестный режим/имена и диагностика. Полный suite также проверяется в LF/CRLF-копиях через `tests/laning/verify_checkouts.py`.

Игровое появление ровно двух героев этим набором тестов **не подтверждено**. Mock Bot API не моделирует заполнение лобби и автоматический выбор движка.

API: [GetGameMode / GetSelectedHeroName / GetTeamPlayers](https://docs.moddota.com/lua_bots/). Код режима 21 соответствует `DOTA_GAMEMODE_1V1MID` в [клиентском enum](https://github.com/SteamTracking/GameTracking-Dota2/blob/master/Protobufs/dota_shared_enums.proto). Это ссылки на поверхность API/enum, не свидетельство успешного запуска команды.
