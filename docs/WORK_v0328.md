Причина потери фарма на этом участке подтверждена, величина регрессии относительно другой игры не является контролируемым benchmark.

Прежняя попытка блокировки через SIDE_SHOP/ROAM не закрывала отдельный режим; ClearActions из ability hook не снижал desire WATCHER, и захват запускался снова.

## Решение

1. Rune-политика и config возвращены к v0.3.25: нет water-pair reset, сохранён ресурсный порог второй воды, нет запрета нижней воды изv0.3.26. Остальные рабочие функцииv0.3.25 сохраняются.
2. Close approach и wrong-way guard применяются к южной руне и при INVALID/unknown type в120–359с. После6мин обычные неизвестные силовые сохраняют прежнюю дистанцию. Это защита от долгого неверного движения, не обещание подбора.
3. `mode_watcher_nevermore.lua` добавлен только в tower_pressure_test: GetDesire0 не позволяет native WATCHER выигрывать выбор. У реактивного watcher hook больше НЕТ игровых приказов, только редкая диагностика неожиданного захвата. Даже если клиент не подключит новый mode entry, код не создаёт прежнюю петлю отмен; возможный нативный захват будет диагностироваться.
4. PT/Stick, Raze, Requiem, покупки/курьер, вардинг/девард и оценка tower pressure не переписываются.

## Проверка и ограничения

14 офлайн-наборов прошли; Lua5.1 синтаксис122файлов. Проверена нулевая desire нового entry и отсутствие отмен/движений от watcher hook за120последовательных секунд, чужие каналы не затрагиваются. Проверены south-water INVALID approach/away-cancel и неизменный power pickup после6мин. Игровой loader/pathing/pickup этим не доказаны.

Следующий тест: не должно быть `ignore_watcher` приказов, native WATCHER не должен занимать SF, LH должны продолжать расти при доступных крипах. Если возникает `watcher_unexpected_capture`, loader нового режима не подтверждён и нужен отдельный разбор; не возвращать секундные ClearActions.

Реальный подбор нижней воды всё ещё открыт. Main не меняется, PR остаётся Draft. v0.3.27 не выпускать. Это целевой recovery-кандидат, не объявленная стабильной сборка.
