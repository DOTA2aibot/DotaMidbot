# #33 — v0.3.2: обычная игра и диагностическая проба

Owner: **Artem (GPT)**. Reviewer: **Олег (Kimi)**. Issue: [#33](https://github.com/DOTA2aibot/DotaMidbot/issues/33). Кандидат подготовлен поверх PR31, синхронизированного с принятой main после PR32.

## Что исправляется

В старой установке собственный `mode_laning_nevermore.lua` заменяет режим линии, даже когда diagnostic runtime не отправляет приказов. Возврат0 после10:00 или удержание HIGH desire при паузе heartbeat не восстанавливают стандартный laning Think.

Выбран явный профиль перед матчем:

| Профиль | Перемещения/обычные атаки | Собственные способности/покупки | Назначение |
|---|---|---|---|
| `valve_play` — по умолчанию | Стандартные режимы движка; собственный mode_laning отсутствует | Да, принятый PR32 сохранён | Проверка обычного матча, в том числе после10:00 |
| `lane_probe` | Собственный диагностический runtime | С уступкой активному runtime-плану | Проверка движения/одной атаки и дальнейшая калибровка T007 |

Это **не переключение на Valve посреди матча**. Probe по-прежнему имеет одну атаку и окно600 секунд; им нельзя оценивать полноценный фарм. Для обычного матча запускать valve_play с самого начала. Неизвестный путь динамического вызова C++ режима не подменён заглушкой или выдуманным API.

Исходник mode_laning перемещён в `profiles/lane_probe/`. `laning/profile.lua` по умолчанию отключает runtime: guard не создаёт heartbeat/lease и возвращает false в AbilityGate, поэтому собственный callback способностей продолжает работать. Сборщик probe генерирует profile с runtime_enabled=true. При случайном вызове runtime в play он не выдаёт приказов; оставленный старый корневой entrypoint всё равно должен быть удалён полной заменой папки.

Модель T007, каталог комбинаций, проверки движения PR31 и механика ACK/TTL остаются в репозитории. Способности и покупки совпадают с принятой main после32. В имени бота **MIDBOT v0.3.2**. В `[MIDBOT selection]` добавлены `controller_profile` и `controller`; manifest содержит профиль, состав/хэши и атрибуцию результатов.

## Сборка и установка

Из корня checkout Python3, без дополнительных зависимостей для сборки:

```powershell
python tools/package_bot.py --profile valve_play --output MIDBOT-v0.3.2-valve-play.zip
python tools/package_bot.py --profile lane_probe --output MIDBOT-v0.3.2-lane-probe.zip
```

Установка подготовленного архива (подставить свою папку игры):

```powershell
python tools/package_bot.py --install MIDBOT-v0.3.2-valve-play.zip --game-dir "C:/PATH/Steam/steamapps/common/dota 2 beta/game/dota"
```

Перед установкой закрыть Dota. Установщик проверяет архив, путь/наличие клиента, сохраняет прежнюю папку как `bots.backup-<UTC>-<id>` и заменяет её целиком. Ничего из старой папки не удаляется; путь копии выводится в результате. Настройки Steam/логирования он не меняет. После установки создать новый матч.

При ручной установке **сначала переименовать старую bots**, затем скопировать новую bots из ZIP. Не извлекать поверх старой папки: отсутствующий в новом ZIP root mode_laning иначе останется на диске и продолжит перехватывать линию. Полный ZIP следует собирать из согласованного актуального снимка; старые ZIP могут вернуть старый файл способностей.

## Игровой тест valve_play

1. Оставить запись консоли включённой. Проверить `MIDBOT v0.3.2` и строку `controller_profile=valve_play controller=valve_native` при выборе героев. После установки в корне bots не должно быть `mode_laning_nevermore.lua`.
2. Записать режим лобби и фактический состав обеих команд. Дополнительные боты пока возможны: это отдельная задача. Такой состав подходит для технического smoke-test, но не считается чистым1v1.
3. Первый короткий участок: наблюдать выход с базы, обычные атаки и работу способностей/закупки. В play **нет собственного лимита одной атаки**; сколько атак выберет стандартный ИИ, нужно увидеть в игре.
4. Пройти за10:00, желательно до12:00–15:00, наблюдая положение, режим и действия SF до/после границы. Если герой снова стоит, сохранить точное время и видео/реплей плюс консоль. Это уже нельзя автоматически объяснять лимитом отсутствующего runtime.
5. Сохранить полный игровой лог, включая файл с суффиксом номера матча, manifest установки и наблюдения. Отсутствие `[MIDBOT runtime]` в play ожидаемо и само по себе не доказывает успешной игры. Нужны видимые действия героя; текущий patch не добавляет непрерывную native-телеметрию из отсутствующего callback.

Ожидается, что собственный диагностический режим больше не удерживает героя. Это ещё не доказательство качества/стабильности стандартного ИИ. Бафф frenzy, точность рейзов, 30LH к10:00 и число смертей проверяются отдельно; автоматическое достижение метрик не обещается.

## Проверки и следующий шаг

```powershell
python -X utf8 tests/laning/run_tests.py
python -X utf8 tests/laning/verify_checkouts.py
```

Помимо прежних180 проверок, проверяются профиль/атрибуция, отключение heartbeat и владения в play, автономность фактического callback PR32, работоспособность probe, состав двух ZIP и замена старого root mode с сохранением резервной копии. Это offline Lua5.1 и файловые тесты, не Dota.

Игровой прогон нового valve_play и отсутствие простоя после10:00 пока **не проверены**. #33 и T007 не закрываются автоматически. После независимого ревью и игрового результата фиксируется статус. Показатели valve_play относятся к стандартному контроллеру с собственными способностями/закупкой; для оценки своей политики нужен отдельный runtime-профиль и согласованные измерения. [ADR0005](adr/0005-controller-profiles.md) остаётся Proposed.
