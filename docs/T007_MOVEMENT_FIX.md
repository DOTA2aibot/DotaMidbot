# T007: кандидат v0.3.1 — проверка перемещений

Owner: **Artem (GPT)**. Reviewer: **Олег (Kimi)**. Задача: [T007 / #7](https://github.com/DOTA2aibot/DotaMidbot/issues/7). Base main: `d17e9bdfa2d9c7de0a177b8b1fbe19f9d4cb28e3`.

## Основание

Локальный лог матча9080972160: на0:21.73 отправлена атака по melee-крипу, на0:22.20 получено `attack_released / new_own_projectile_and_attack_record`. В интервале0:00–2:30 связь была готова во всех290 runtime-записях, наблюдалось36 `move_completed`, но45 перемещений прервались с `unsupported_order`. Точную физическую причину этих отказов старый лог не содержит. Новые сценарии воспроизводят классы отказов на подставном API, а не проигрывают матч.

В прежнем коде любой геометрический шаг к mid добавлялся как available без проверки проходимости. В свежем Submit известный шаг move с `movement_valid=false` попадал в общий `unsupported_order`. Неисправная точка могла снова выбираться в следующих решениях.

## Изменённое поведение

| Файл | Назначение изменения |
|---|---|
| `laning/runtime/movement.lua` | Единая проверка координат, длины, проходимости и наблюдаемых вышек. Подбор ограниченного локального шага |
| `laning/runtime/backend.lua` | Проверка до выбора и повторно перед Action API; masked candidate вместо невалидного приказа; поле `movement` в логе |
| `laning/runtime/config.lua` | Только идентификатор build/run: `v0.3.1-T007-movement-candidate`, `movement-probe-01` |
| `hero_selection.lua`, `CHANGELOG.md` | Patch-версия **MIDBOT v0.3.1**, без изменения выбора героев/линий |
| `tests/laning/` | Регрессии выбора/отправки движения, геометрии и актуального имени бота |

Прямой шаг по-прежнему максимум250 units. Если он недопустим, проверяются направления0/±30/±60 градусов с длинами полного/половины/четверти шага. Каждый вариант должен уменьшать расстояние до прежней цели. Всего максимум15 вариантов за один расчёт; выбирается первый проверенный. Открытая прямая сохраняет прежний шаг и не перебирает альтернативы.

Проходимость проверяется у конечной точки и по отрезку с интервалом не более50 units; угрозы вышки — также по семплам. Это консервативная локальная проверка, **не глобальный поиск пути** и не доказательство реального маршрута движка между семплами. U-образное препятствие, необходимость временно отойти от цели или отсутствие безопасного локального шага приводят к ожиданию, а не гарантированному обходу. Самопроизвольного увеличения шага/дальности нет.

Если после ACK герой сместился и прежняя точка оказалась дальше лимита, приказ отвергается с `move_step_too_long`; новый план рассчитывается из нового положения. Приказ не удлиняется молча и старая цель не подменяется другой внутри Submit.

Невалидная точка получает конкретную причину: `move_point_impassable`, `move_path_impassable`, `move_step_too_long`, `move_enters_tower_range`, `move_tower_range_unknown`, `move_passability_unavailable`, `move_passability_failed`, `move_vector_unavailable`, `move_position_invalid` или `move_tower_data_unavailable`. Неизвестное значение не считается разрешением двигаться.

## Что сохранено

`operation=lane_probe`, `stage=attacks`, максимум один атакующий приказ на загрузку, heartbeat и отдельный ACK плана, TTL0.35, ограничения опасности/близкого героя и все калибровочные поля false. Каталог вариантов и оценочная модель не меняются. Число повторных атак не увеличивается.

Файл способностей и покупки сохранены побайтово из base. Найденный после3:29 `IsMoving` остаётся отдельной работой **Олега (Kimi)**. Этот patch не обещает исправления способностей. В принятом PR30 native1v1 всё равно появился состав5 ботов против человека; новый patch не меняет количество слотов. Такой состав допустим для технической проверки приказов, но не для измерения чистого1v1 и ML-данных.

## Проверки вне игры

Среда: Python3.13, Lupa2.8, Lua5.1. Команды из корня снимка:

```powershell
python -X utf8 tests/laning/run_tests.py
python -X utf8 tests/laning/verify_checkouts.py
```

Результат: **180 offline проверок** =160 прежних+8 runtime-регрессий движения+12 проверок геометрии/отказов. Полные LF/CRLF-прогоны прошли; изменённые pinned fixtures отвергаются во всех4 отрицательных проверках. Одна из новых регрессий предварительно воспроизведена на прежнем коде: полностью непроходимое движение ошибочно оставалось available. Наличие Lua-тестов не подтверждает navmesh, стоимость API и поведение в реальной Dota.

## Как проверить в Dota

1. Провести независимое ревью PR. После merge брать полный актуальный снимок main; если исправление способностей уже принято отдельно, сохранить его. Не накладывать старый полный ZIP поверх более новой main.
2. Сохранить текущую папку bots и установить согласованный комплект целиком, включая новый `laning/runtime/movement.lua`. Для кандидата из отдельной ветки честно записать его SHA и наличие/отсутствие соседнего исправления способностей.
3. Новый локальный матч с записью лога с запуска. Проверить имя **MIDBOT v0.3.1**, build/run_id. Настройки `lane_probe`/лимит1/false-поля не менять. Противника первую пробу держать на базе или вне900 от SF. Записать фактический состав обеих команд.
4. До2:30 наблюдать выход на mid, ожидания/обходы и одну атаку по крипу. После одной атаки отсутствие постоянного фарма ожидаемо. Если нет движения или атаки, не повышать лимиты: сохранить причины.
5. Завершить матч/закрыть клиент и сохранить полный игровой файл лога. Dota может продолжить журнал в файле с суффиксом номера матча; нужны строки `[MIDBOT runtime]`, не только стартовый файл без суффикса.

В записи движения ожидаются `movement.phase=selection/validation/submission`, `origin`, `destination`, `distance`, `reason`; при альтернативе — `alternative=true`, `attempts`, `blocked`; при отказе семпла — `failed_sample`, при вышке — `tower_id`. Точные поля могут отсутствовать, если отказ произошёл до чтения этих данных. Диагностика относится к проверке движения, а не автоматически к выбранной атаке в той же записи.

Успех: допустимые шаги дают `submit→move_completed`, атака даёт `submit→attack_released`; недопустимые варианты ждут с точной причиной без `unsupported_order` для move и без вызова Action API на запрещённую точку. `move_completed` подтверждается позицией, не таймером. Новый игровой прогон ещё **не выполнен**; до него patch остаётся кандидатом, T007 не Done.
