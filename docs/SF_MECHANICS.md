Подготовлено 2026-11-07 для переработки T007. Это справочник требований к планированию, не утверждение о проверенном игровом результате.

Установленный build Олега пока не известен; runtime может отличаться. Не обозначать автоматически профиль как «проверенный 7.41f на нашем ПК».

Это справочные текущие значения, **не зашитые production-константы**. Runtime читает собственные `GetSpecialValueFloat`, `GetManaCost`, `GetCastPoint`, `GetCooldownTimeRemaining`, текущие статы и модификаторы. Если поле/поведение изменилось, опция получает маску, а не правдоподобное выдуманное число.

## Урон и стаки

Оценка сырого рейза при известных данных:

```text
(runtime base damage + runtime damage-per-soul × current souls
 + runtime stack bonus × unexpired stacks ON THIS TARGET) × own spell amplification
```

Затем отдельно применяется магическая защита/модификаторы цели. Первый рейз по новой цели не получает стаки с другого героя. Промах не добавляет стак. Между кастами учитываются expiry/возможный dispel и фактическая геометрия. Последовательность «два рейза» не равна автоматически «два попадания».

В планировщике регистрируются предполагаемые попадания; в исполнении после каждого события нужно перечитать **реальный** модификатор цели. Имя модификатора и доступность его stack-count должны быть проверены в установленном клиенте. Отсутствующий/недоступный счётчик — unknown, не автоматически 0.

## Атаки, броня, души и предметы

- Для немедленного удара брать текущий total attack damage и damage-query цели. Total уже включает существующие души, атрибуты, обычные бонусы предметов. Повторно прибавлять их нельзя.
- Текущая броня цели уже может содержать Presence. Нельзя снова вычитать ту же ауру поверх engine damage-query.
- Для гипотетического перемещения аура может появиться/пропасть. Это новый state; старое effective damage не гарантирует результат после смены позиции.
- Крита, proc, attack modifier, damage block и spell absorb нельзя без проверки превратить в общий линейный множитель. При неизвестном нелинейном эффекте соответствующая оценка маскируется.
- `mechanics.lua` принимает уже измеренный `attack_damage_effective`. Для изменения числа душ можно передать отдельные engine-derived queries по числу душ; иначе рост душ не добавляется к атаке повторно. Если души должны уменьшиться и новой оценки нет, она остаётся unknown.
- При прогнозируемом добивании души не превышают **актуальный** max; без известного max будущий прирост не выдумывается. Временные души/баффы Feast должны иметь expiry/границы. Неразрешённые временные эффекты или истёкшее окно валидности урона маскируют длинный план.

Сейчас упрощённый симулятор принимает наблюдаемые числовые оценки и интервалы ошибки. Он не является полной симуляцией всех механик Dota. Прогнозируемое добивание — признак кандидата, а не доказанное событие/reward.

## Информация о враге

Видимые HP/мана/уровень/позиция сохраняются с временем и источником. После потери видимости они получают статус last_seen. Enemy cooldown не считывается из скрытого handle: оценка начинается только после подтверждённого увиденного каста. Интервал CD содержит допущения о CDR/reset; готовность всё ещё возможна. Видимая нехватка маны исключает только конкретную известную способность, а не все угрозы героя/предметов.

## Временные цели

Пуш первой волны/под 2:00, 4:00, 6:00 и работа с катапультой — цели из задания Артёма и гайда Олега. Они не включаются безусловно по часам: учитываются wave state, clear/travel feasibility, HP/мана/опасность и видимые объекты. Пятая минута — cue ожидаемой siege-wave, а не утверждение о позиции катапульты.

Для installed game mode надо отдельно подтвердить расписание рун/крипов. Нельзя переносить стандартные правила All Pick в любой режим 1v1 без проверки. `schedule_verified=false` запрещает автоматический pre-rune push по неподтверждённому расписанию; видимая живая катапульта может дать siege-контекст независимо от часов.
