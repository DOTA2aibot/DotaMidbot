Вариант A: direct API плюс отдельный ранний выбор видимой AVAILABLE river rune до500 включительно, независимо от маны/Bottle/волны/обычной hero target. Retreat/эвейжн, активный каст/стан/очередь, низкоеHP, tower range и оценка смертельного урона не обходятся. Допускается один видимый соперник с известным малым трёхсекундным уроном, не обещается победа в бою. Bounty исключены. История точек и лимит неудач сохраняются.

Вариант B: те же правила, но ActionQueue_PickUpRune вместо direct; отдельная сборка с rune_pickup_transport=queued. Очередь только из IDLE/NONE с пустой очередью, чтобы не пристроить pickup за бесконечным движением/атакой. Нет утверждения, что этот вызов обходит движковый дефект. Лог rune_order содержит transport. Не смешивать A/B внутри одного матча.

Вариант C: штатный native rune pickup. Не внедрён: отсутствие Think или возвратnil из callback не доказывают точечный C++ fallback. Потребуется отдельный диагностический профиль; нельзя ради воды менять рабочее управление всей игрой.

A/B офлайн проверяются на реальные Lua callbacks, но движок/тайминги не эмулируются. В игре ещё не проверены. Успех только фактическое получение воды/зарядов, не submitted=true. Ни одна сборка не устанавливается автоматически. Main и v0.3.28 на компьютере сохранены.
