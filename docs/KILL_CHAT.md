# T022 — «??» в all-чат после убийства

Owner: **Artem (GPT)**. Reviewer: **Олег (Kimi)**. [Issue №44](https://github.com/DOTA2aibot/DotaMidbot/issues/44). Пользователь явно поручил отправлять ровно одно сообщение `??` после убийства, без паузы; создать PR и не мержить.

## Изоляция и подключение

`laning/social/kill_chat.lua` содержит отдельную небольшую логику. `kill_chat_config.lua` задаёт включение и лимиты. В `laning/observer/entry.lua` добавлен только необязательный защищённый вызов; существующие Capture, shadow, wards и корневые callbacks не переписаны.

Вызов находится до проверки observer_enabled, поэтому отключение телеметрии само по себе не отключает чат. У чата собственный переключатель `enabled`. В диагностическом профиле с runtime_enabled=true чат не запускается. Отсутствие или ошибка модуля сохраняют прежний цикл наблюдения и способностей.

Dispatch теперь явно включает разрешённый пользователем косметический side effect. Чистые сборщик состояния и shadow-политика остаются read-only. Единственный игровой API-вызов нового модуля: `ActionImmediate_Chat("??", true)`. Pause/DebugPause, движение, атаки, очистка команд, применение способностей и покупки не вызываются.

PR подготовлен отдельно от PR41 и PR43. Он не меняет их корневые файлы способностей/закупки, hero_selection, packager, общий CHANGELOG или номер игровой сборки. Модуль помечен версией `kill-chat-1`; сам PR не является самостоятельным игровым релизом. Общие version bump/CHANGELOG резервируются за координатором интеграции перед выпуском объединённой сборки. До этого PR остаётся Draft и не обозначается Done. Ветки не требуется вливать друг в друга для работы над модулями.

## Когда отправляется сообщение

Источник — увеличение `GetHeroKills(playerID)` настоящего собственного SF. Требуются известные имя героя, IsHero, IsIllusion=false, ID бота и состояние alive. Иллюзии отсекаются до чтения счётчика и не изменяют baseline. LH, assists или исчезновение противника не являются поводом для чата.

Это kill credit игрока SF: счётчик не доказывает конкретную жертву или атакующий юнит. Например, убийство собственной иллюзией может быть записано игроку, но сами копии никогда не отправляют сообщение. Эта защита относится только к чату; она не исправляет остальные геройские callbacks иллюзий из предыдущего разбора.

При первом вызове принимается текущий счётчик, старые убийства не воспроизводятся. Pregame, смерть/респавн, сброс счётчика, перемотка времени или разрыв callbacks больше 2 игровых секунд сбрасывают ожидающие уведомления и принимают новый baseline. Это сознательно предпочитает пропуск устаревшего сообщения его поздней отправке.

Проверка счётчика — не чаще 4 раз в секунду. Multi-kill создаёт ограниченную очередь до 5 сообщений с интервалом не меньше 3 реальных секунд; срок жизни записи — 15 реальных секунд. Переполнение/истечение срока допускают пропуск уведомления, а не поток старых сообщений. RealTime не останавливается вместе с игровой паузой; сам модуль никогда не ставит паузу.

Курсор и очередь обновляются до вызова чата. При исключении после отправки попытка того же kill number не повторяется. Лог `[MIDBOT kill-chat]` различает chat_call_returned и chat_call_failed_no_retry; в обоих случаях доставка остаётся unknown. Void API и локальный лог не доказывают отображение сообщения у всех игроков: возможны mute/rate limit/настройки клиента.

```powershell
python -X utf8 tests/social/verify_checkouts.py
python -X utf8 tests/laning/run_tests.py
```

Отдельный набор использует реальный Lua 5.1 модуль и actual entry/ability callbacks с подставным игровым API: обычный kill, повторы, старт с ненулевым счётчиком, иллюзии с тем же ID, чужой герой/человек/unknown, multi-kill/overflow/TTL, смерть/gap/reset, ошибки API/логгера/helper, выключенный observer и диагностический runtime. Пауза и посторонние игровые команды в fixture запрещены. Дополнительно тот же callback smoke можно выполнить с `--ability-source <файл из PR43>` без включения кода PR43 в этот PR.

Сборщик уже включает все `laning/**/*.lua`, поэтому новый root mode или отдельный установщик не нужен. Для выпуска достаточно согласовать общий номер сборки и установить полный проверенный пакет; сейчас установка и merge не выполняются.
